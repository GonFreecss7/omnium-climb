# New features — implementation prompt

Implement the following eight features. Build and verify each one
independently against its acceptance criteria before moving to the next.

---

## 1. Cross-filter: technique ↔ drill

**What:** From a technique detail view, show which drills train it. From a
drill detail view, show which techniques it develops. Bidirectional.

**Approach:** Derive the relation from shared tags/category at build time
(in the parse step, not at runtime) and emit `relatedDrills: string[]` /
`relatedTechniques: string[]` into each JSON entry. Render as a chip list
linking to the related entry's detail view.

**Acceptance:**
- [ ] Every technique detail view shows a "Related drills" section (hide it
      if empty, don't show "no results")
- [ ] Every drill detail view shows a "Related techniques" section
- [ ] Links navigate correctly in both EN and ES
- [ ] Relation data is generated by `npm run parse`, not computed at runtime

---

## 2. Random technique of the day

**What:** Same pattern as the existing "Random drill" feature — a button
that surfaces one random technique from the full set.

**Approach:** Mirror the existing random-drill component/logic exactly.
Place it symmetrically (same position in the Techniques tab as Random Drill
occupies in the Drills tab).

**Acceptance:**
- [ ] Button surfaces a random technique on tap, re-rolls on repeat taps
- [ ] Visually consistent with the existing Random Drill card
- [ ] Works offline

---

## 3. Session history export (JSON / CSV)

**What:** Export all locally stored Session Log entries to a file the user
can save/share, in JSON or CSV.

**Approach:** Read from the existing session store. Generate the file
client-side, trigger a native download via Blob + object URL. Offer both
formats behind a small format picker (two pills, matching the existing
toggle style).

**Acceptance:**
- [ ] Export produces a valid, correctly UTF-8-encoded file (ES accents
      render correctly)
- [ ] CSV has a header row; JSON is an array using the existing session
      schema
- [ ] Works fully offline
- [ ] Empty session history → export disabled, no broken/empty file

---

## 4. Warm-up generator

**What:** Generate a short randomized sequence of drills, one per category,
for a pre-climb warm-up.

**Approach:** New view or modal. Let the user pick how many categories to
include (default: all, or a sensible short subset — this is a warm-up, keep
it brief). Pull one random drill per selected category. Support rerolling
one individual drill without resetting the whole set.

**Acceptance:**
- [ ] Generates 1 drill per category, no duplicates in the same set
- [ ] Individual drill reroll works independently of full-set reroll
- [ ] Readable at 380px width, no horizontal scroll
- [ ] EN/ES for all UI text

---

## 5. Shareable session checklist

**What:** User selects a set of drills + techniques for today's session and
generates a clean, shareable/printable view.

**Approach:** Reuse existing list/card components with checkbox-style
selection. Output view is a simple, high-contrast layout with a print
stylesheet (strip nav/tab bar/toggles when printing). Share via Web Share
API where available, clipboard fallback otherwise.

**Acceptance:**
- [ ] User can select techniques + drills from existing lists
- [ ] Generated checklist is legible in light/dark and in print
- [ ] Share button works via Web Share API; clipboard fallback confirmed
- [ ] No data leaves the device — local generation only

---

## 6. Combined-filter search

**What:** Extend search to filter by category + tag simultaneously, not
just free-text.

**Approach:** Add filter chips above the search input (reuse chip
component). Filters are additive (AND) with free-text query. Active
filters shown as removable chips.

**Acceptance:**
- [ ] Category + tag filters combine correctly with free-text query (AND)
- [ ] Clearing filters returns exactly to today's unfiltered behavior
- [ ] Active filters visible and removable
- [ ] Works in EN and ES, including translated tag/category labels

---

## 7. Progressions view

**What:** A curated, ordered view grouping techniques/drills into a
suggested learning sequence (e.g. static footwork → dynamic movement →
dynos), instead of the flat category list.

**Approach:** Define the progression as content data, parsed at build time
like everything else — not hardcoded in a component. Align the sequence
with the app's existing focus (V1–V4, dynamic/power movement).

**Acceptance:**
- [ ] Progression data is generated into JSON by the parser
- [ ] View renders an ordered, navigable sequence with clear stage labels
- [ ] Each stage links to the real technique/drill detail views, no
      duplicated content
- [ ] EN/ES for all stage labels and descriptions

---

## 8. Personal notes per technique

**What:** Free-text note field per technique, saved locally.

**Approach:** Same local storage layer as Session Log, keyed by technique
ID. Autosave on blur/debounce; show a saved/unsaved indicator if autosave
has any delay. Plain text only, no rich formatting.

**Acceptance:**
- [ ] Note persists across app restarts and offline
- [ ] Note field appears in technique detail view, collapsed by default
- [ ] Reasonable max length (e.g. 2000 chars) with a visible counter near
      the limit
- [ ] Deleting all text removes the stored entry rather than keeping an
      empty string indefinitely

---

## General acceptance (re-verify after all features land)

- [ ] `npm run build` succeeds clean
- [ ] `npm run parse` regenerates all data (techniques, drills, relations,
      progressions) with no manual steps
- [ ] No console errors/warnings introduced
- [ ] App still fully functional offline after first load
- [ ] No accounts, sync, backend calls, or gamification introduced
